# Native 属性更新：跳过布局样式构造

这项优化用于 Plico 默认桌面后端，不改 LVGL。共享核心已有 StyleProperties /
FrameDelta，桌面后端也已有脏节点同步、Taffy style 比较和绘制缓存。
因此不能把 LVGL 中减少 setter 的收益直接当成桌面后端的预期收益。

## 本次变化

此前每个被同步的节点都会先构造完整 Taffy Style，再与缓存比较；对于 paint-only
更新，最终 style_writes 虽然是零，构造和比较仍执行。

现在使用现有字段标记宏生成的 Style::layout_eq，比较**动画与交互处理后的**样式。
布局输入不变时复用缓存，不构造 Taffy Style。不能只检查声明的属性位：动画、hover
和宿主窗口变化可以在没有新声明的情况下改变最终样式。

- 新节点、种类变化、布局属性变化和 root 尺寸变化正常构造布局。
- 文字变化复用布局配置，但文字测量失效照常传播，不能跳过 Taffy 排版。
- 普通主题颜色变化不构造布局；Switch/Checkbox 的主题 metrics 变化保留更新。
- GridTemplate 是 Copy Style 之外的可变长数据，目前保守处理：存在模板或刚移除
  模板时仍构造布局，避免仅靠 layout_eq 漏掉轨道变化。
- BackendStats.layout_style_builds 记录构造次数，与实际 style_writes 分开。

## 实验

```sh
cargo run --locked -p plico-vello --example property_work
# 也可自行使用 --release；下表不是 release 数据。
```

固定 480×360 视口，32/256/1024 行，每行一个背景容器和文字；只切换第一行的
颜色、等长文字或宽度，另测全局 panel 主题色。故意不虚拟化，其他行多数在视口外。
每组预热 10 帧、测量 40 帧。通过 render_retained_frame 包含真实声明、布局、
文字与场景构建，但**不创建窗口、不提交 GPU、不等待 VSync**。

2026-10-23 本机 dev profile（opt-level=1），以 4b9fd7e 的 backend 源码为基线，
与本次实现各运行三轮、交替顺序；表中是三轮均值的中位数，单位 µs：

| 行数 / 场景 | 同步阶段：前 → 后 | 整体 CPU 帧：前 → 后 |
| --- | ---: | ---: |
| 32 / 主题颜色 | 26.85 → 23.45 | 244.74 → 284.41 |
| 256 / 主题颜色 | 214.50 → 190.03 | 617.23 → 600.16 |
| 1024 / 主题颜色 | 919.38 → 817.33 | 2256.54 → 2218.94 |
| 1024 / 单节点颜色 | 0.23 → 0.47 | 764.94 → 770.70 |
| 1024 / 单节点文字 | 1.00 → 1.02 | 1464.18 → 1524.03 |
| 1024 / 单节点尺寸 | 1.00 → 1.02 | 1464.95 → 1516.17 |

全局主题更新的同步阶段约减少 11%；单节点同步本来就很短，没有证明整帧性能提升。
整体结果有明显噪声，小场景主题甚至变慢，不能宣称稳定的总帧加速。
现有 sync_micros 只有微秒精度；示例的 layout_us 是后端现有 layout_micros 计数，
包括该阶段的其他工作，不能等同于纯 Taffy 排版时间。

确定性回归断言证明：paint-only 动画与主题颜色变化零次布局样式构造；文字更新仍
测量，尺寸动画仍布局，窗口 resize 仍更新，Grid 和 toggle 密度变化仍正确。
后续更值得测量声明、全局几何维护与场景生成的占比，而不是继续假设属性比较是主瓶颈。
