# 路线图

## 1. 稳定身份、状态和提交协议

引入框架状态槽位与 revision，减少手工 changed；允许直接借用外部业务状态。明确卸载、隐藏、控件类型变化、schema version 与 best effort reset。定义可重复声明中的副作用边界。

验收：条件分支、列表重排/删除/插入不会错配状态；一个点击只执行一次业务动作；同帧文字与主题一致；失败帧不会启动推测任务。

## 2. 原生文本输入

将原 Wabou 的 native text widget 直接复制进本仓库维护（当前精简后的内置后端尚未包含该控件），验证控件生命周期、焦点、选择、剪贴板、IME preedit/commit 和候选窗口位置，不自己快速拼一个假编辑器。

验收：程序更新文本与用户编辑互不覆盖；多个输入框切换无残留 composition；重排不丢焦点/选择；真实平台输入证据与 headless 测试分开记录。

## 3. 迁入模拟时钟、动画和任务语义

先迁入确定性测试，再连接真实时钟、wake 和执行器。继续使用 request/generation 拒绝旧结果，任务只在最终提交启动。

验收：retarget 连续、卸载清理、动画结束休眠、任务去重/取消/超时/乱序完成。测量大量动画的声明、布局与绘制分别消耗多少。

## 4. 做一个真实工具

包含搜索、动态列表、文本编辑、异步加载与失败重试、主题和少量解释状态的动画。与 egui 实现同样的任务，比较规则负担、调试体验、输入正确性和实际开销。

验收不只看代码行数或截图。不要在这个阶段扩张到完整组件库。

## 5. 提炼可嵌入运行时与 Bevy 插件

从本仓库内维护的实际桌面宿主边界提炼输入/时间/场景与资源协议，保留同一套 UI 行为。先支持一个嵌入 surface，再扩展多个 camera/window/DPI 与输入仲裁。优先共享运行时，不强制转换成 Bevy 原生控件。

验收：同一组件在桌面与 Bevy 中可用；输入不穿透到游戏逻辑；UI 销毁释放资源；无动画时不要求持续更新；明确渲染/资源兼容边界。

## 6. 可选 authoring 工具与 best effort hot reload

默认 Rust/rustfmt 已好用，再迁入可选 formatter。恢复原 LSP 与幂等测试。当前 CLI 已默认启用 best effort hot reload：兼容状态通过 Serde 恢复，不兼容时重置整个 App，编译/加载失败保留上一可用版本。后续再探索局部状态恢复；当前验证见 reports/hotreload/report.json。

此顺序是当前优先级，不是对用户功能需求的硬限制。先解决可验证的问题，再根据证据调整。
