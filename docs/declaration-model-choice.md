# 声明模型：immediate mode

2026-10-22 选择 immediate 声明作为主线，2026-10-23 删除 reactive Runtime、
依赖图实验和依赖它们的旧应用；Rune 闭包转换实验也已删除。

当前路径是事件驱动声明、保留树、属性比较和失效 journal。宿主保留文字、布局与绘制缓存，
可以独立推进动画和滚动；不要求每个呈现帧重新声明业务 UI。

响应式实验显示，维护依赖、生命周期、宿主唤醒和热重载边界的成本很高。
这不足以证明 reactive 在所有场景更慢，也没有证明全量声明永远足够便宜。
Plico 先保持普通 Rust 的借用、函数与控制流，通过实际应用测量决定优化范围。

后续优先减少重复分配、文字整形、无关布局和宿主输出工作。有实际热点时再考虑显式区域
memo；不把自动依赖收集或长期业务闭包作为默认作者模型。
