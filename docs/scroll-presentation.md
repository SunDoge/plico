# 滚动声明与宿主表现分离

2026-10-21。参考本机 MyGO runtime 中“重新构建 view / 仅重绘已有内容”的分层，继续使用 Plico 原有 retained 节点、增量后端和注入时钟，没有引入信号、订阅图或 memo。

## 已实现

之前平滑滚动的每个偏移变化都标记应用声明失效。现在滚动插值返回两个信息：画面是否改变、改变的容器是否在上次声明时读取了滚动几何。

- **普通滚动容器**：不读取 scroll_viewport 时，中间帧只更新宿主几何和 Scene，不执行 show，不重新运行 Taffy 布局。
- **虚拟列表或位置相关内容**：读取 UiContext::scroll_viewport 的容器，在自身偏移改变时仍重新声明。现有 VirtualList 自动通过同一读取路径登记，无需新增应用参数。
- **按容器记录**：初次读取即使还没有反馈、返回 None，也记录观察；下一次成功声明若不再读取，就清除该标记。没有“任意一处读过滚动就让所有容器失效”的全局开关。
- **事件几何**：事件准备阶段可直接提交当前滚动位置用于命中测试。最后一个滚动位置若在事件准备时完成，随后事件即使未命中控件，也会请求绘制尚未呈现的 Scene 版本，避免最终位置缺一帧。

实现为节点上的一个 Cell<bool> 元数据和 advance_scroll 的失效分类；不新增每帧分配、应用状态或运行时依赖。点击、编辑等输入仍可请求声明，不能理解成所有滚动期间的输入都不执行 UI。主动 build_frame 快照接口继续保留其显式构建语义；优化主要用于 native retained 帧。

## 验证与实验

```sh
cargo test -p plico-backend --test scroll_presentation
cargo run --release -p plico-backend --example scroll_work
```

六个回归覆盖：普通滚动中间帧跳过声明/布局且几何更新；读取偏移时失效并可停止观察；10000 行虚拟列表在呈现位置声明、节点数量有界；事件准备使用当前几何；首次 None 反馈和按容器观察；最终滚动帧在未命中事件下仍请求绘制。既有平滑滚动、窗口变化、输入和虚拟列表测试也通过。

性能示例使用 1000 个固定高度行容器及其文本，共 2002 个后端节点，预生成标签以免 format! 分配混淆结果。22 个往返滚动周期，前两个预热，其余各采样 10 个 16ms 虚拟时钟中间帧；每条件 200 次 CPU 样本。三轮各自 p50 的中位数：

| 条件 | p50 | 每采样 show 次数 | Taffy layout 次数 | 几何展开节点数 |
|---|---:|---:|---:|---:|
| 普通容器，仅宿主表现 | 897 µs | 0 | 0 | 2002 |
| 同场景，每帧强制 request_rebuild 对照 | 1142 µs | 1 | 0 | 2002 |
| 显式读取滚动位置 | 1143 µs | 1 | 0 | 2002 |

相对于强制声明对照，普通容器样本耗时约减少 21%。这是同一版本中的受控路径对比，不是老版本二进制对比。当时第一帧 wheel 事件后的声明不在中间帧采样内，仍会执行；下述第二轮消除了这个额外声明。没有窗口、GPU 提交或 present，不据此推断 FPS 或整体应用加速。

## 第二轮：滚轮事件本身不强制声明

2026-10-23。之前 Source 把每个 EventResponse.request_redraw 都转为 pending 声明。
即使普通滚动插值已经跳过 show，实际滚轮输入仍每次执行一次 show；平滑虚拟列表在
事件准备阶段更新可见行后，又因目标重定向执行一次相同位置的声明。

现在后端内部将事件的声明失效与重绘请求分开，公开 EventResponse 和应用 API 不变：

- 普通容器的滚轮只改变宿主滚动偏移或动画目标，不触发 show。
- 观察滚动位置的容器直接改变偏移时仍触发声明，包括关闭平滑滚动或 reduced motion。
- 平滑滚动仅改变目标时不声明；后续实际偏移变化仍按原有容器观察标记更新虚拟行。
- 直接滚动的 dirty 几何会在下一次事件准备或 retained 帧提交，即使没有进行声明。
- 已提交但尚未绘制的最终滚动位置只请求重绘，不使无关业务声明失效。
- 其他输入、待处理外部更新、逻辑动画及显式构建快照的语义不变。

可重建探针：

```sh
cargo run --release -p plico-backend --example wheel_work
cargo test -p plico-backend --test scroll_presentation
```

探针包含真实 wheel 分发、shell 相同的 prepare_for_event、后端提交和 CPU scene 编码，
使用 16ms 虚拟时钟、预生成日志字符串，240 次采样中后 200 次计时。普通列表有 1000 行，
每行容器加文字；虚拟列表有 100000 行数据，仅声明可见行和 overscan。没有窗口、GPU
提交或 present。修改前后各运行三轮，以下为三轮 p50 的中位数：

| 场景 | 修改前 | 修改后 | show 次数/采样（前 → 后） |
|---|---:|---:|---:|
| 普通列表，直接滚动 | 1076 µs | 882 µs | 1 → 0 |
| 普通列表，平滑滚动 | 1224 µs | 884 µs | 1 → 0 |
| 虚拟列表，直接滚动 | 47 µs | 46 µs | 1 → 1 |
| 虚拟列表，平滑滚动 | 56 µs | 49 µs | 2 → 1 |

普通列表本机 CPU 样本下降约 18% / 28%。虚拟列表直接滚动的微小差异不视为收益，
它仍必须更新可见行。两条普通路径均无 Taffy layout；滚动几何展开和 scene 编码仍存在。
回归额外覆盖反复 wheel、观察/未观察、平滑/直接滚动组合，实际鼠标命中新位置，
虚拟行在后续输入前挂载，以及外部更新不被表现快路径吞掉。

## 边界

- 每帧仍完整展开滚动几何、更新空间/命中信息，并重新编码场景；结果不是 O(1)，未做 GPU-only scroll 或局部绘制命令片段。
- 观察只按容器和读取行为分类，未按可见行范围变化进一步跳过 VirtualList 声明。
- dev 热重载 replay 当前为传递反馈而读取所有滚动容器，仍保守地触发声明；没有更改模块协议，不能宣称 dev 获得相同收益。
- 可变高度列表、行锚点和 prepend 保持位置仍未实现。本轮优化不替代这些功能。
