# 主题切换与呈现动画

默认过渡为 200 ms 圆形揭示。首次切换以指针位置为原点，键盘操作使用窗口中心。
动画只改变呈现，语义状态与命中几何立即提交；结束后恢复事件驱动休眠。
resize/DPI 改变会结束旧尺寸动画。

`Source::set_theme_transition_duration(Duration::ZERO)` 可以关闭过渡；宿主也可通过
reduced-motion 策略关闭呈现动画。组件本身不读取系统时间，Source 使用注入的时钟采样。

## 有界的端点场景

主题切换不为每个中间颜色重新整形文字。Source 缓存两个未合成的主题端点场景，
每帧只改变目标场景的圆形 clip；实际栅格化、文字缓存和 damage 交给后端。
这仍需要回放场景，不是 O(1) 的截图纹理转场，也不保证全屏主题切换只有小面积 damage。

在两个主题间快速反向时，保留同一揭示原点与两份端点，只把当前揭示进度的目标
改为 0 或 1。反向瞬间的几何保持连续，当前主题端点的业务内容仍可更新。
不要把已经合成的动画帧再次作为端点：它会把历史场景递归带进下一次过渡。
旧实现频繁切换时会累积场景与隔离图层，最终触发 wgpu 的 128 MiB 帧预算错误。

切换到这两个端点之外的第三套配色时，从上一份**未合成**目标重新开始过渡。
这里优先保证场景持有量有界，不承诺第三套配色的中断瞬间完全连续。
清理动画、resize 和关闭动效都会释放端点场景。

## 验证

`plico-runtime` 单元测试使用模拟时间验证开始、中间帧、反向瞬间一致性、结束、
resize 和关闭动画；连续 100 次快速切换后场景命令数仍为两份端点加一层 clip。

`plico-wgpu` 的 `layers` GPU 测试使用真实 Source 和一个含透明隔离层的界面，
连续 80 次每隔 30 ms 反转主题，断言图层帧预算保持有界，并比较动画结束与关闭
动画后的完整像素。此测试需要 GPU，不加入常规 CI：

```sh
cargo test --locked -p plico-wgpu --test layers rapid_theme_reversal -- --include-ignored
```

运行时错误现在分别报告实际嵌套深度和实际字节预算请求，避免把两种限制混为一谈。
128 MiB 的保护预算保持不变。
