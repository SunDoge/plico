# 2048：对照 MyGo 的应用切片

Gallery 侧栏新增 **2048**，参考本机 `/home/me/code/go/2048/main.go` 和 `game.go` 的布局、配色、稳定棋子身份和动画时序，以 Plico 的普通 Rust 状态与 children 重新实现。没有引入 MyGo 运行时，也没有修改参考仓库。

```sh
cargo run -p gallery
# 在侧栏选择 2048，方向键 / WASD / HJKL 移动，R 重开。
# 屏幕上的方向按钮也能操作。
cargo plico dev
```

## 实现与对比

| 能力 | 本地 MyGo 2048 | Plico gallery |
|---|---|---|
| 经典棋盘、分数、最高分、New game | 有 | 有，棋盘随 viewport 宽高缩放；页面保留滚动以支持更小尺寸 |
| 2048 规则 | 每块每步合并一次、成功移动后生块 | 相同规则；2/4 按约 90%/10% 生成 |
| 棋子身份 | tile ID | 业务 ID；移动保留 Entity，新合并块取得新 ID |
| 滑动 | 100ms | 100ms；快速输入从当前采样位置继续移动 |
| 新生块 / 合并弹跳 | 延迟 100ms，随后 200ms | 相同时序；尺寸居中增长，合并峰值 1.2 倍 |
| 被合并的旧块 | ghost 滑入目标 | ghost 留在新块下方直到 300ms |
| 得分提示 | 600ms 上浮与淡出 | 600ms 上浮与淡出 |
| 胜负提示 | 延迟较长的透明遮罩 | 350ms 后开始淡入，600ms 完成；继续 / 重开可用 |
| 输入 | 方向键、WASD、HJKL、R、Cmd+N、拖拽、触控板 | 方向键、WASD、HJKL、R、屏幕方向按钮 |
| 状态保存 | 文件 / 浏览器存储 | 当前应用状态与 best-effort reload；未写磁盘 |
| 金色棋子 glow / inset shadow | 有 | 当前只有经典填色，无专门阴影 |
| 无障碍结束播报 | 有 | 文字和按钮进入语义树，未接 live announcement |

默认使用固定种子的轻量伪随机序列，方便重放；重开会推进序列。种子随模块状态保存。
这里是 gallery 应用切片，不是已经覆盖参考版全部平台能力的独立游戏。

## 框架补充

- `Layout::absolute(left, top)`：局部绝对定位，不进入 flex 流，不会像 overlay 一样提升为窗口 portal。
  后端映射到 Taffy absolute/inset；负坐标可用，非有限坐标被拒绝。
- `UiContext::viewport_size()`：逻辑 viewport 宽高。原生宿主与模块协议都传入实际大小，模块在 resize 时重新声明。
- `plico_dev::App::on_key` 与 `set_frame_time`：普通应用也能接收未被控件消费的无修饰按键，静态 App 与动态模块共享同一处理函数。
  模块请求的 `keys` / `viewport` 与响应 `key_handled` 是可选字段，旧消息默认无按键。
- 输入法组合、文本输入的可打印字符、modal/popover 优先，不由游戏快捷键截获。

游戏的持久规则状态、临时动画状态都是可序列化字段。布局示例仍使用 children；只有动态棋子和棋盘格需要业务 key。
没有长期事件闭包，也没有每个棋子各自的计时器。每次动画声明从注入的 `FrameTime` 采样，动画完成停止请求帧。

后续已迁移到 **固定布局 + translate / scale / opacity 绘制变换**，不再逐帧改尺寸、坐标和字号。
动画中间帧不重排；开始移动及移除临时节点仍可能布局。失效分类、子树传播和工作量见 [presentation motion](presentation-motion.md)。

## 验证

规则测试覆盖四方向、单次合并、成对合并、无效移动不消耗随机数、得分、胜利后继续、失败、重开和状态序列化。
真实后端测试用虚拟时钟检查 0/50/600ms 的位置变化、Entity 复用、动画结束空闲、640×740 棋盘范围、按钮和胜负操作。
模块协议测试覆盖按键只执行一次、注入时钟和 viewport、状态延续。

实际动态库验证会加载 gallery、通过语义侧栏进入游戏、发送方向键、采样动画，再激活同一编译产物的新副本并检查棋盘/分数：

```sh
cargo build -p gallery --lib --no-default-features --features abi
cargo run -p plico-desktop --example game2048-reload -- --module target/debug/libgallery.so
```

这是 Linux 动态库 ABI 与激活路径的验证，不是跨平台 watcher 或不兼容 schema 的完整迁移证明。
另在 Xvfb 隔离的 X11 会话中实际启动 gallery，点击 2048 侧栏并发送方向键，确认棋盘区域画面变化。

截图工具可以固定棋盘和时钟，避免只看静止画面：

```sh
cargo run -p gallery --example capture -- --page 2048 --game-sample --out reports/2048/gallery.png
cargo run -p gallery --example capture -- --page 2048 --game-sample --dark --width 640 --height 740 --out reports/2048/small-dark.png
cargo run -p gallery --example capture -- --page 2048 --game-sample --game-move --game-ms 50 --out reports/2048/move-050.png
cargo run -p gallery --example capture -- --page 2048 --game-sample --game-move --game-ms 200 --out reports/2048/move-200.png
cargo run -p gallery --example capture -- --page 2048 --game-sample --game-move --game-ms 600 --out reports/2048/move-600.png
```

`--game-sample` 明确设置演示分数/棋盘，不是玩家的真实成绩。
